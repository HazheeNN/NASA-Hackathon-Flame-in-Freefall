# Decisions

Newest first. Each entry: date, decision, why, who. Add one whenever you choose between real options, so the next person (or Claude) doesn't reopen it.

- **2026-11-14** **Agent Reach for web research, per laptop, pinned v1.6.1** (owner). Installed with `uv` on each teammate's laptop (`docs/runbook.md`), not in the repo; the repo carries only the `web-research` skill with our rules: default channels only, no login channels, findings it turns up are leads to follow to a NASA source, never sources themselves. Why: YouTube transcripts of NASA talks and pages the built-in fetch can't read, at no cost. Not installed or tested in the cloud session that set this up (installing third-party tools was blocked there).
- **2026-11-14** **Homepage = Flame Lab; NASA Horizon-inspired design; live site shows only verified data** (Shera, with Claude). Home is an interactive flame lab (conditions, WebGL flame, four world cards with real NASA photos, tested-in-blue / untested-in-red, insights for the chosen world, fire-only mode); Four Worlds and the Habitat Designer merge into it. The flame is a labelled illustration: shape and colour follow NASA-documented trends, it computes nothing; every number comes from verified data or a NASA formula in range (keeps the no-simulator decision). Design moves to NASA's Horizon typefaces (Public Sans, DM Mono), near-black and white with one accent, real photography; never NASA's logo or header. Only verified records reach the live site (`src/lib/visibility.ts`: hidden when `VERCEL_ENV=production`); Vercel previews and local dev show unverified ones with their badge so the team can review the UI. Ask becomes a search dialog (Ctrl/⌘ K) plus /ask. Inspired by, not copied from, another team's public Fotia console. Supersedes the "mission-control console, IBM Plex" design entry.
- **2026-11-14** **No Chinese data; FLEX Table IX is our first real dataset** (Shera, with Claude). No data from Chinese agencies, missions, institutions or databases; NASA and partner agencies only (`docs/data.md` › No Chinese data). FLEX Table IX (NASA/TP—2015-216046, 276 ISS tests) is real, public and checked against the PDF: we parse it from the NASA PDF ourselves rather than copying another team's CSV (no licence, another entry). Fire-atlas data is dummy and not used. api.nasa.gov has no combustion data; we use only its image library and TechPort.
- **2026-11-14** **NASA formulas: explain everywhere, compute only inside the tested range (option C)** (Shera, with Claude). Everything we calculate must come from equations in NASA (or partner agency) sources. Each formula is a record with its source and page, variables, units and validity range (gravity, O₂, pressure, flow, material). The Habitat Designer and Four Worlds compute with a formula only when every input is inside its range; outside, they show "outside tested conditions" and point to the gaps map. Computed values carry a "calculated" label and the formula's citation; measured findings stay visually distinct. No formula we can't cite, no fitting our own curves, no chaining formulas into a risk score. Why: the team wants the site grounded in NASA's own physics; limiting it to tested ranges keeps the honesty rule (`Validity` criterion) and stays clear of the rejected simulator. `docs/data.md` › Formulas.
- **2026-11-14** **Feature set: confidence meter, gaps map (must), Same Fire Four Worlds, Habitat Designer; Life of a Flame on hold** (team, with Claude). Four Worlds shows each world's sourced conditions and documented differences, **no simulator**. The Habitat Designer uses NASA-sourced presets and filters findings by conditions; **it never computes a risk score** (that would be the predictive model we rejected). All four sit on one condition space (gravity, O₂, pressure, airflow). Added "What NASA should test next" (SI-proposed experiments for the biggest gaps) and real, credited NASA flame images. Cut: compare two experiments, export; the 0 g vs 1 g chart, explainer and flammability map fold into Four Worlds and the gaps map. Why: most teams build a chart dashboard or a predictor; the gaps map and test-next list are the most direct value to NASA, and honesty about thin partial-gravity data becomes a feature. Sources to collect: `docs/data.md` › Sources for Four Worlds….
- **2026-11-13** **No API key for now: the SI runs in Claude Code sessions (mode A)** (owner). The three SI jobs live in `prompts/`; a teammate runs them in Claude Code on our Pro plan, the output is validated, reviewed and committed, and the app makes no AI calls at runtime. Ask becomes a library of 20–30 prepared, cited answers with search, instead of a live chatbot. Why: no API spend, nothing to fail on stage, every answer reviewed. Tradeoff: judges can't type a free question to a live AI. The API scripts stay in `scripts/` (mode B) in case we get a key; switching back is in `docs/ai.md` › Mode B. Supersedes the `LIVE_SI` and live-advisor parts of the entries below.
- **2026-11-13** **Collaborate in one repo, not forks** (proposed): teammates are added as collaborators on `HazheeNN/NASA-Hackathon-Flame-in-Freefall` and work on branches. A fork works too (PRs from the fork), but one repo means one CI, one Vercel project and no syncing. Confirm on Day 0.
- ~~**2026-11-13** **Demo safety switch `LIVE_SI`**~~ (mode B only now): `off` (or no API key) makes the app use only pre-built insights and cached answers. Why: a live API call on stage is the biggest single risk.
- **2026-11-13** **Human verification gate**: Claude-extracted findings land in `data/raw/proposed/` and reach `data/findings.json` only after a person checks them; `verified` is shown in the UI. Why: validity is a judging criterion, and AI extraction can be wrong.
- **2026-11-13** **Pre-built insights, committed to git**: ranking runs offline (now in Claude Code, mode A) and the output is reviewed and committed. Why: fast, free at demo time, reviewable, can't fail on stage.
- **2026-11-13** **Whole-corpus prompting, no RAG / vector DB**: the corpus (≈ 100 findings) fits in one prompt; prompt caching makes repeats cheap. Why: simpler, nothing to break, and the model can link findings across experiments.
- **2026-11-13** **Claude Opus 5.5 (`claude-opus-5-5`) for all SI** (in Claude Code for mode A; `CLAUDE_MODEL` overrides it in the mode-B scripts). Why: the most capable default model, 1M context, cheaper than earlier Opus. In mode A it costs only Pro usage.
- **2026-11-13** **No database**: JSON in `data/`, validated with Zod at build. Why: tens to hundreds of read-only records; a DB adds setup, secrets and a failure point.
- **2026-11-13** **Stack: Next.js 16 + TypeScript + Tailwind 4 on Vercel**, Recharts for charts, Lucide icons. Why: most polished result in 2 days with the stack we already use (Deployment Report); static pages are fast and robust.
- **2026-11-13** **Dark theme only, English only, no accounts.** Why: scope. One theme done well beats two half done; check readability on a projector.
- **2026-11-13** **Design reference: mission-control console reading a NASA report, with the microgravity flame sphere as the brand.** IBM Plex Sans + Mono. Why: credible, distinctive, and the flame sphere tells the science story in one image (`DESIGN.md`).
- **2026-11-13** **No NASA insignia or logotype**, and a "not affiliated with or endorsed by NASA" line in the footer. Why: NASA doesn't permit their use on third-party projects.
- **2026-11-13** **Seed experiments are marked unverified**: the foundation was written without access to NASA sites, so every seed fact must be checked and its NTRS search link replaced with a real citation.
